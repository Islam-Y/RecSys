# Воспроизведение исследования

В проекте есть два уровня проверки: аудит опубликованных q48-артефактов без обучения и повторный запуск пайплайна на Yambda-50M. Метрики относятся к offline-ранжированию сэмплированных кандидатов.

## Аудит q48 без обучения

Скачайте `recsys-q48-artifacts.zip` и `SHA256SUMS` из [релиза q48-v1](https://github.com/Islam-Y/RecSys/releases/tag/q48-v1) в одну папку, затем выполните:

```bash
shasum -a 256 -c SHA256SUMS
unzip recsys-q48-artifacts.zip
python3 recsys-q48/verify_metrics.py
```

Аудит проверяет контрольные суммы и пересчитывает NDCG@3/Recall@3 для 7 025 запросов и 3 365 пользователей. Для пользовательских 95% bootstrap-интервалов установите NumPy из окружения проекта и добавьте `--bootstrap`. На Linux вместо `shasum -a 256` используется `sha256sum`.

## Повторный запуск baseline

Нужны Python 3.11+ и зависимости из `requirements.txt`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdir -p data/raw
curl -L --fail --output data/raw/yambda-50m-multi_event.parquet https://huggingface.co/datasets/yandex/yambda/resolve/main/flat/50m/multi_event.parquet
python -m recsys_mvp prepare-yambda data/raw/yambda-50m-multi_event.parquet --query-sample-modulo 2500 --negatives-per-query 50 --negative-strategy mixed --popular-pool-size 50000 --seed 42
python -m recsys_mvp baseline data/processed/yambda_candidates.parquet --history-input data/processed/yambda_history.parquet --output-dir outputs/yambda-hard-negatives
```

В этой выборке позитив — Listen+ (`played_ratio_pct > 50`); неизвестные кандидаты — смесь популярной и равномерной выборок. Это не реальные показы без клика. Полное описание протокола и временного разбиения — в [отчёте](Отчёт.md).

## Повтор проверки стоимости признаков

Основной эксперимент требует нормализованной истории и candidate-файлов предыдущих когорт. Точный список входов и выбранные восемь формул зафиксированы в `experiments/feature-efficiency-selection.json`; протокол — в `experiments/feature-efficiency-protocol.md`. После подготовки всех перечисленных входов:

```bash
python -m recsys_mvp.feature_efficiency
```

Результаты сохраняются локально в `outputs/feature-efficiency/`. Для истории остальных серий используйте протоколы в `experiments/` и соответствующие записи в [журнале исследования](История-исследования.md). Локальные данные и результаты запусков в Git не входят.
