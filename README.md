## MVP

Пайплайн умеет профилировать CSV/TSV/Parquet и обучать pointwise CatBoost baseline на таблице кандидатов с явными бинарными метками. DuckDB считает признаки по взаимодействиям за 1, 7 и 30 дней: активность пользователя, популярность объекта и историю пары. События с тем же timestamp и события из будущего не попадают в историю.

### Контракт входной таблицы

Для команды baseline обязательны колонки user_id, item_id, timestamp, label. Метка должна быть 1 для целевого взаимодействия и 0 для кандидата, который действительно был показан, но не получил целевого взаимодействия. Для группировки кандидатов в запросы можно передать query_id; иначе запрос задаётся сочетанием пользователя и timestamp.

**Не превращай отсутствие события в отрицательную метку.** Если есть только положительные события, начни с profile; после аудита данных нужно определить корректный источник кандидатов и негативов.

### Запуск

Используй Python 3.11 или новее:

    python3.14 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python -m recsys_mvp profile data/interactions.parquet
    python -m recsys_mvp baseline data/candidate_examples.parquet

Если имена колонок в файле отличаются, укажи их через параметры --user-column, --item-column, --timestamp-column, --label-column и --query-column. Baseline и JSON с метриками сохраняются в outputs/baseline/. Сырые данные и результаты локальных запусков в Git не попадают.

Temporal split сейчас использует глобальные квантили timestamp 70/15/15. Это исходный протокол MVP; после аудита датасета его нужно сверить с реальной постановкой отбора. Метрики validation используются для итераций, test следует оставить для финальной оценки.
