## MVP

Пайплайн умеет профилировать CSV/TSV/Parquet и обучать pointwise CatBoost baseline на таблице кандидатов с явными бинарными метками. DuckDB считает признаки по взаимодействиям за 1, 7 и 30 дней: активность пользователя, популярность объекта и историю пары. События с тем же timestamp и события из будущего не попадают в историю.

### Контракт входной таблицы

Для команды baseline обязательны колонки user_id, item_id, timestamp, label. В задаче CTR метка 0 должна соответствовать кандидату, который действительно был показан, но не получил целевого взаимодействия. Для группировки кандидатов в запросы можно передать query_id; иначе запрос задаётся сочетанием пользователя и timestamp.

**Не превращай отсутствие события в отрицательную метку без оговорок.** Если в данных нет показов, адаптер может сэмплировать неизвестные объекты для offline ranking, как ниже; это отдельный протокол с отдельными ограничениями.

### Первый эксперимент: Yambda-50M

Использован официальный [Yambda-50M](https://huggingface.co/datasets/yandex/yambda) — срез из 10 тыс. пользователей и примерно 934 тыс. треков. Датасет распространяется под Apache 2.0; его карточка указывает научные и исследовательские цели публикации. Сырые данные и все результаты остаются вне Git.

В Yambda нет логов показов без взаимодействия. Поэтому для исследовательского ranking-протокола позитивом считается прослушивание более 50% трека, а отрицательные кандидаты случайно выбираются из треков, доступных к моменту запроса и ещё не встречавшихся в истории пользователя. Это **сэмплированные неизвестные**, а не реальные «показ без клика»; метрики нельзя трактовать как качество CTR-модели или онлайн-эффект.

Скачать источник и воспроизвести запуск:

    mkdir -p data/raw
    curl -L --fail --output data/raw/yambda-50m-multi_event.parquet https://huggingface.co/datasets/yandex/yambda/resolve/main/flat/50m/multi_event.parquet
    python -m recsys_mvp prepare-yambda data/raw/yambda-50m-multi_event.parquet --query-sample-modulo 5000 --negatives-per-query 20
    python -m recsys_mvp baseline data/processed/yambda_candidates.parquet --history-input data/processed/yambda_history.parquet --output-dir outputs/yambda-baseline

Препроцессор сформировал 5 029 временных запросов, 5 631 позитивный и 100 130 отрицательных кандидатов. Для генерации признаков использовалась полная история Listen+ из датасета, а не только сэмплированные строки кандидатов. В каждом признаке учитываются только события строго раньше времени запроса.

```mermaid
flowchart LR
    A[Полные события Yambda] --> B[Listen+ история]
    A --> C[Запросы и кандидаты]
    B --> D[Point-in-time признаки]
    C --> D
    D --> E[CatBoost]
    E --> F[NDCG@3 / Recall@3]
    C --> G[Тот же candidate set]
    G --> H[Baseline популярности]
    H --> F
```

| Отложенная выборка | CatBoost | Ранжирование по популярности за 30 дней |
|---|---:|---:|
| NDCG@3 | 0.8327 | 0.7949 |
| Recall@3 | 0.8734 | 0.8538 |

На тесте также получены AUC 0.9199 и log loss 0.0999. Тест содержит 750 запросов; случайные негативы делают задачу заметно легче, чем ранжирование реальных показов. Считать результат предварительным: следующий эксперимент должен сохранить тот же temporal split, но проверить более сложный popularity-weighted negative sampling и абляции временных окон.

### Запуск

Используй Python 3.11 или новее:

    python3.14 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements.txt
    python -m recsys_mvp profile data/interactions.parquet
    python -m recsys_mvp baseline data/candidate_examples.parquet

Если имена колонок в файле отличаются, укажи их через параметры --user-column, --item-column, --timestamp-column, --label-column и --query-column. Baseline и JSON с метриками сохраняются в outputs/baseline/. Сырые данные и результаты локальных запусков в Git не попадают.

Temporal split сейчас использует глобальные квантили timestamp 70/15/15. Это исходный протокол MVP; после аудита датасета его нужно сверить с реальной постановкой отбора. Метрики validation используются для итераций, test следует оставить для финальной оценки.
